# Runtime topology

DagFlux has two cooperating layers.

## The interactive layer

This is what you see and click on: the workflow canvas, the chat panels
beside each node, the connections list, the execution history view, and
the settings screens. It builds and edits the workflow but never holds
your secrets or talks directly to your databases.

When you ask DagFlux to do anything that touches a credential or runs a
piece of generated logic, the interactive layer asks the background
engine to do it.

## The background engine

Always running in the background while DagFlux is open. It is responsible
for:

- Keeping your AI provider keys and connection credentials encrypted at
  rest.
- Loading the available connectors (database integrations, cloud storage
  integrations) and AI skills.
- Talking to external systems on your behalf — running queries, fetching
  files, calling APIs, embedding text, upserting vectors.
- Calling AI providers to generate operations on demand.
- Watching for scheduled triggers and file-system changes, and starting
  workflows when they fire.
- Executing nodes in order and writing the result of every step into the
  execution history.

## What's stored locally

Inside your user data directory, DagFlux maintains:

- An encrypted file holding your AI provider keys.
- An encrypted file holding the secret parts of every saved connection
  (passwords, tokens, API keys).
- A workflows store with every workflow you've created.
- A connections store with the public parts of every saved connection
  (name, type, hostname, etc.).
- An executions store with the full history of every workflow run.
- A chat sessions store with the conversations you've had with the AI
  assistant inside each node.
- A single shared SQLite database that holds every "local" import and
  every locally-stored transformation result.
- Local document-store files for any data you choose to import or
  produce in document form.

You can see and manage everything from inside DagFlux; nothing is sent
anywhere automatically.

## How communication is shielded

Generated operations use placeholders for sensitive values. For example,
a REST API fetch generated by the AI references the connection's base
URL and credentials by symbolic name, not by literal value. The literal
values are filled in only inside the background engine, just before the
operation runs. The interactive layer therefore never holds a decrypted
key, and saved workflows never contain one either — even if you were to
share the workflow file with someone else, your secrets would not travel
with it.

## Telemetry

DagFlux can record anonymous, opt-in telemetry about which operations
are used and how long they take. Telemetry is off by default and is
toggled from the settings screen and the terms-and-conditions flow.
Nothing about your data, your prompts, or your credentials is ever
included.
