# Connectors

A connector is the bridge between Ternlux and one external system: a
database, a vector store, a cloud bucket, a spreadsheet service, a REST
API, or a local file format.

Each connector tells Ternlux:

- How to test that the connection works.
- How to list the things you can read from (tables, collections,
  buckets, indexes).
- How to list the columns or fields of one of those things.
- How to run a query, fetch records, upload an object, or whatever the
  underlying system supports.
- Optionally, how to write the AI prompt that produces transformations
  for that specific system, so the AI uses the dialect's idioms.

## Categories

### Relational databases (SQL)

Generated transformations produce SQL. Joins produce SQL with
temporary tables when needed. Each connector implements its dialect's
identifier quoting, preview syntax, and supported types.

| Connector | Notes |
| --- | --- |
| [PostgreSQL](postgres.md) | Multi-schema, SSL support, system schemas hidden |
| [MySQL](mysql.md) | Standard pooling, dialect-specific batch inserts |
| [MSSQL (SQL Server)](mssql.md) | Named instances, default `dbo` schema |
| [BigQuery](bigquery.md) | Google data warehouse, dataset.table naming, partitioning |
| [Snowflake](snowflake.md) | Cloud warehouse, account identifier, warehouse + role context |
| [Redshift](redshift.md) | AWS warehouse, JDBC URL parsing |

### Document databases

Operations are object-shaped (collections, filters, aggregation
pipelines). Generated transformations may use filters, updates,
deletes, aggregation, or custom JavaScript.

| Connector | Notes |
| --- | --- |
| [MongoDB](mongodb.md) | Aggregation pipelines, batched JS transformations |

The local document store (NeDB) is also available for any workflow
that imports JSON or generates documents — see
[Connections](../../connections/README.md).

### Vector databases

Special paths in joins, outputs, and the AI assistant handle
embeddings and similarity search. See the
[Vector Database Executor](../skills/vector-db-executor.md) skill for
the full embedding and upsert behaviour.

| Connector | Notes |
| --- | --- |
| [Pinecone](pinecone.md) | Cloud vector index, namespace-as-table model |
| LanceDB | Local vector database — no plugin needed, available everywhere out of the box |

### Cloud storage

File picker UX and bucket / object listing screens. See
[Cloud storage](cloud-storage/README.md).

| Connector | Notes |
| --- | --- |
| [Amazon S3](cloud-storage/s3.md) | AWS keys, S3-compatible endpoints (MinIO, etc.) |
| [Google Cloud Storage](cloud-storage/gcs.md) | Service account JSON or key file |
| [Azure Blob Storage](cloud-storage/azure-blob.md) | Connection string or account key |
| [Google Drive](cloud-storage/google-drive.md) | OAuth, file IDs, format export |
| [OneDrive](cloud-storage/onedrive.md) | OAuth, Microsoft Graph, multi-tenant |
| [SharePoint](cloud-storage/sharepoint.md) | OAuth, Microsoft Graph, site / drive model |
| [Dropbox](cloud-storage/dropbox.md) | OAuth, team-space detection |

### Spreadsheet services

| Connector | Notes |
| --- | --- |
| [Google Sheets](google-sheets.md) | OAuth, spreadsheetId + sheetName as table identifier |

### REST API

| Connector | Notes |
| --- | --- |
| [REST API](rest-api.md) | Generic HTTP integration with four auth schemes; per-data-source fetch logic generated by the AI |

### Local file formats

These don't need a connector — they're imported into the local
workspace by the Data Source node. Supported formats: CSV, Excel,
Parquet, Avro, JSON (into a local document store), SQLite, NeDB,
LanceDB.
